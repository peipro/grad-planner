# 平板与局域网同步 · 改动说明

> 本文档说明"桌面端 ↔ 平板/手机"局域网共享的完整机制，以及本轮对平板使用逻辑做的所有修改。

---

## 一、整体架构：两端如何共享同一份数据

```
                    ┌─────────────────────────────────────────────┐
                    │        data\sync\grad-planner-storage.json   │  ← 唯一数据源
                    └─────────────────────────────────────────────┘
                        ▲ 写                      ▲ 写（同一文件）
                        │                         │
              ┌─────────┴──────────┐     ┌────────┴─────────────┐
              │  桌面端 (Electron)  │     │  平板/手机 (浏览器)    │
              │  渲染进程 ──IPC──▶  │     │  fetch PUT/GET/DELETE │
              │  主进程写文件        │     │  /api/storage         │
              └────────────────────┘     └──────────────────────┘
```

- **桌面端**：React 渲染进程 → `window.electronAPI`（IPC）→ 主进程写文件
- **平板端**：浏览器打开局域网地址 → `public/sync-adapter.js` patch 了 `localStorage`，把 `grad-planner-storage` 这个键的读写重定向到 HTTP `/api/storage`
- 两端读写的是**同一个 JSON 文件**，天然就是"共享同一份数据"

## 二、平板端怎么用（现在）

1. 桌面版启动 → 自动开启局域网服务（端口 8899，占用则顺延），生成 32 位随机 token
2. 打开「设置」→「局域网共享」卡片，看到访问地址（形如 `http://192.168.3.15:8899/?token=…`）
3. 平板/手机（同一 WiFi）用浏览器打开该地址 → 加载同样的前端 + 同步适配层
4. 任一端修改，另一端约 1 秒内自动刷新

## 三、本轮改了什么（核心）

### 1. 平板端写入节流 —— `public/sync-adapter.js`

**问题**：之前平板端每次状态变更（点一下、敲一个字）都立即发起一次**整份 JSON 的 PUT**。访问日志里能看到每 0.5 秒一次的 PUT 风暴，浪费流量、易丢请求。

**修改**：500ms 内的连续写入合并为一次；页面关闭/刷新前用 `keepalive` 兜底发送，不丢最后一次修改。

```js
// 浏览器端写入节流：高频 setState 时合并 PUT
var pendingPut = null
var putTimer = null
function flushPut() {
  if (putTimer) { clearTimeout(putTimer); putTimer = null }
  if (pendingPut === null) return
  var v = pendingPut
  pendingPut = null
  fetch(API_PATH, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: v,
    cache: 'no-store',
    keepalive: true,           // 页面关闭时也能把最后一份数据发出去
  }).catch(function () {})
}
function remoteSet(value) {
  if (isElectron) return window.electronAPI.syncStorageSet(String(value)).catch(function () {})
  pendingPut = String(value)
  if (!putTimer) putTimer = setTimeout(flushPut, 500)
}
window.addEventListener('pagehide', flushPut)
window.addEventListener('beforeunload', flushPut)
```

### 2. 桌面端写入节流 —— `electron/main.cjs`

**问题**：桌面端每次 `setState` 都同步整文件写盘。

**修改**：300ms 内合并为一次落盘；退出前强制 flush，不丢数据。

```js
ipcMain.handle('sync-storage-set', (_e, data) => {
  if (typeof data !== 'string') return { ok: false, error: 'invalid data' }
  pendingSyncData = data
  if (!syncWriteTimer) syncWriteTimer = setTimeout(flushSyncWrite, 300)
  return { ok: true }
})
// app.on('will-quit', () => { flushSyncWrite(); ... })
```

### 3. 原子写 —— `electron/lan-server.cjs` / `main.cjs`

**问题**：直接 `writeFileSync` 覆盖数据文件，崩溃/断电会把唯一数据源写坏。

**修改**：先写临时文件再 `rename` 替换，任何时刻磁盘上都有一份完整数据。

```js
write(data) {
  let tmp = null
  try {
    fs.mkdirSync(path.dirname(file), { recursive: true })
    tmp = `${file}.tmp-${process.pid}-${Date.now()}`
    fs.writeFileSync(tmp, data, 'utf-8')
    fs.renameSync(tmp, file)   // 原子替换
    return { ok: true }
  } catch (e) { /* 清理 tmp 后报错 */ }
}
```

### 4. 同步刷新守卫 —— `electron/main.cjs`

**问题**：平板一写，桌面端就无条件 `webContents.reload()` 整页刷新，会丢失正在编辑的内容，还连翻译小窗一起刷。

**修改**：
- 按**内容哈希**判断文件是否真的变了，没变就不刷（防止无意义刷新/刷新循环）
- 跳过翻译小窗，只刷主窗口
- 桌面端自己的写入 800ms 内豁免，不触发刷新

```js
syncWatcher = fs.watch(dir, { persistent: false }, (evt, name) => {
  if (name && name.endsWith('grad-planner-storage.json')) {
    if (Date.now() - lastDesktopWrite < 800) return   // 自己的写入，跳过
    clearTimeout(syncNotifyTimer)
    syncNotifyTimer = setTimeout(() => {
      const h = storageHash()
      if (h === null || h === lastReloadHash) return   // 内容没变，跳过
      lastReloadHash = h
      reloadRenderers()
    }, 300)
  }
})
```

### 5. token 安全 + 热重置 —— `electron/lan-server.cjs` / `main.cjs`

**问题**：访问日志把带 `?token=…` 的完整 URL 写进 `lan-access.log`，令牌泄露；且令牌无法更换。

**修改**：
- 日志只记路径、去掉查询串（含回归测试）
- `setToken()` 支持**热重置**：重置后已连接设备立即失效，无需重启服务

```js
// lan-server.cjs
function log(method, url, status, req) {
  const pathOnly = String(url).split('?')[0]   // 不记 token
  ...
}
return { ..., setToken: (t) => { tokenRef = String(t || '') } }

// main.cjs
ipcMain.handle('lan-reset-token', () => {
  const token = crypto.randomBytes(16).toString('hex')
  fs.writeFileSync(path.join(app.getPath('userData'), 'lan-token.txt'), token, 'utf-8')
  if (lanInstance && lanInstance.setToken) lanInstance.setToken(token)
  return { ok: true, token }
})
```

### 6. 设置页管理面板 —— `src/views/SettingsView.tsx`

新增「局域网共享」卡片：显示访问地址、一键复制、重置令牌，并提示重置后需用新地址重连。

新增 IPC：`lan-info`（返回端口/token/本机地址）、`lan-reset-token`（重置令牌），经 `electron/preload.js` 暴露为 `electronAPI.lanInfo / lanResetToken`。

## 四、安全说明（已知边界，如实告知）

| 项 | 现状 |
|---|---|
| token 存储 | 明文 `data\lan-token.txt`（本机文件） |
| token 传递 | 走 URL query，仅局域网内 |
| 日志 | 已脱敏，不记录 token |
| 传输 | 明文 HTTP，同网段可被嗅探（个人局域网场景可接受） |
| 鉴权 | `/api/storage` 强制 token，静态页面开放 |

## 五、如何验证这些改动生效

1. 桌面端「设置 → 局域网共享」应能看到访问地址与「复制地址 / 重置令牌」按钮
2. 平板打开地址后，连续快速操作，观察网络面板：PUT 请求应被合并（不再是每步一次）
3. 平板修改后，桌面端约 1 秒内刷新且不丢未保存输入
4. 点「重置令牌」后，平板刷新页面应立即 401（旧 token 失效）
